A finished project only tells part of the story. The interesting details often live in the decisions, experiments, and small lessons along the way.

This is an **example entry** for this notebook. Replace it with a story of your own, or use the outline below as a starting point.

## Start with the question

What were you trying to build, understand, or change? Give the reader a little context before getting into the details.

For a project, that might mean describing the problem and who it affects. For a learning note, it could be a question that sent you down a rabbit hole.

> A useful story doesn’t have to cover everything. One clear idea, explored honestly, is enough.

## Show the process

Describe the choices that mattered, including the approaches that didn’t work out. Screenshots, small code examples, and specific observations can make the process easier to follow.

### A small code example

Fenced code blocks include syntax highlighting:

```ts
const notes = ["Build something", "Notice what happens", "Write it down"];

for (const note of notes) {
  console.log(note);
}
```

Use `inline code` for a function name, a command, or a small technical detail.

### Make the tradeoffs visible

| Part of the story  | What to include                           |
| ------------------ | ----------------------------------------- |
| The starting point | The problem, constraints, and first idea  |
| The experiment     | What you tried and what happened          |
| The decision       | What you chose and why                    |
| The outcome        | What changed and what is still unresolved |

## Keep the useful details

A project write-up might include:

1. A short explanation of the problem.
2. The approach and the reasons behind it.
3. A working example or a screenshot.
4. The outcome, limitations, and next steps.

A learning note can be much smaller:

- Something that surprised you.
- An explanation in your own words.
- A link to a useful reference, such as the [Astro Markdown guide](https://docs.astro.build/en/guides/markdown-content/).

## Leave room for what comes next

End with what you learned, what you would change, or a question you still want to explore. The next entry can pick up where this one leaves off.
